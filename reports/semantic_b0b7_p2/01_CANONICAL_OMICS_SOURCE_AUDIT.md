# Canonical RNA/CNA 来源与缺失掩码核验

**结论：原始源表 → raw 缓存 → canonical 基因矩阵的实际数值、基因顺序和缺失掩码全部精确重建；未发现 canonical 提前进行跨患者填补。** 本次未读取任何生存结局数组或外折评测结果，未训练、未前向、未修改历史数据或冻结科学源码。该结论仅涉及数据来源和算子保真，不构成模型性能证据。

## 实际来源与构建算子

1. Phase7-P0 读取 PanCancer Atlas 的 `data_mrna_seq_v2_rsem.txt` 与 `data_log2_cna.txt`。按患者仅选择样本类型 `01`；存在多个原发肿瘤 aliquot 时，以排序后的列在 float32 中计算 `nanmean`。本队列实际全部 512 人各只有一个合格源列。
2. 首列基因符号经缺失转空串、去首尾空白、转大写；删除空符号及字面 `NAN`，按符号排序。同符号的多行按患者计算 `nanmean`。
3. RNA 在符号合并前进行 float32 `log2(x+1)`；CNA 保留源表 signed LOG2-VALUE，不再取对数。合并结果转 float64 存储。自然缺失不由其他患者数据填充。
4. Phase7A 原样继承 Phase7-P0 的 raw/canonical 组学与患者顺序。对两个容器中的七个继承数组已逐元素核验；双方容器均匹配各自历史 manifest，且 Phase7A manifest 精确绑定该 parent 容器。

源码定位：`scripts/phase7_p0_biology_prompt_audit.py:69`（原始测量读取）、`:105`（符号合并）、`:291`（两源文件）、`:321`（保存）；`scripts/phase7a_foundation_survival_headroom.py:123`（继承）、`:148`（保存）。当前消费接口 `src/bgb_en/data.py:103` 使用 canonical 数值，`:106` 从其有限性生成真实测量 mask。

本次服务器数值重建为逐元素精确相等。历史其他环境曾出现 float32 对数核舍入备注，本次无需以该备注替代真实数值核验，也未修改缓存。

## 缺失与队列来源的实证关系

| 队列 | 人数 | RNA canonical 有缺失人数 | RNA 缺失单元格 | CNA 有缺失人数 | CNA 缺失单元格 |
|---|---:|---:|---:|---:|---:|
| COAD | 382 | 144 | 434,160 | 0 | 0 |
| READ | 130 | 59 | 177,885 | 130 | 260 |

RNA canonical 的 203 名缺失患者每人缺 3,015 个基因，其余 309 人无缺失；raw 对应患者每人缺 3,024 源行。CNA canonical 的两列缺失**恰好发生于全部 READ 130 人**，COAD 382 人均观测完整。

这是已验证的来源相关缺失结构。缺失值不是零表达或正常拷贝数；CNA 的这部分缺失与队列来源完全重合，不能把由此可解码的来源差异解释为独立分子机制。RNA 平台原因仍须由独立平台记录证明，本次没有根据缺失形状推断平台或生物学病因。

## 证据、优势与限制

- **优势：** 同时验证原始表、历史 manifest、parent 继承、符号映射、数值与 mask，排除了仅比较两个派生缓存而自洽的风险；保留原始 NaN，不改正在运行的实验。
